# ติดตามน้ำไทย

แดชบอร์ดสรุประดับน้ำในแม่น้ำ เขื่อนขนาดใหญ่ ฝน และพยากรณ์อากาศ ครอบคลุมทั้งประเทศ และเลือกดูรายจังหวัดได้ ใช้บนมือถือได้ (ติดตั้งเป็นแอปบนหน้าจอหลักได้) รันฟรีบน GitHub โดยไม่ต้องเปิดคอมทิ้งไว้

## ทำงานอย่างไร

```
ทุก 15 นาที  GitHub Actions ──ดึง──▶ ThaiWater (ระดับน้ำ, ฝน) + กรมชลประทาน (เขื่อน)
                   │
                   ▼ แปลงเป็นไฟล์ JSON + สะสมประวัติ
             GitHub Pages (สาขา gh-pages) ──▶ หน้าเว็บบนมือถือ
                                                  │
                                                  └─▶ Open-Meteo (พยากรณ์ 3 โมเดล, น้ำท่า GloFAS)
```

| ข้อมูล | แหล่ง | ความถี่ | ประวัติที่เก็บ |
|---|---|---|---|
| ระดับน้ำแม่น้ำ (~800 สถานี) | คลังข้อมูลน้ำแห่งชาติ (สสน.) | ทุก 15 นาที | 14 วัน รายชั่วโมง |
| ฝนสะสม 24 ชม. (~4,000 สถานี) | คลังข้อมูลน้ำแห่งชาติ (สสน.) | ทุก 15 นาที | 120 วัน รายวันรายจังหวัด |
| เขื่อนขนาดใหญ่ 35 แห่ง | กรมชลประทาน | รายวัน | 400 วัน |
| พยากรณ์ฝน / อุณหภูมิ / ลม | Open-Meteo (ECMWF, GFS, ICON) | เรียกสดตอนเปิดดู | – |
| พิกัดอำเภอ 928 แห่ง | ขอบเขตอำเภอจาก OpenGISData-Thailand (คำนวณจุดกลาง) | ไฟล์คงที่ | – |
| คาดการณ์ปริมาณน้ำท่า 30 วัน | Open-Meteo Flood API (GloFAS) | เรียกสดตอนเปิดดู | – |

## ความสามารถ

- **สรุป** — ตัวเลขสำคัญ และบทวิเคราะห์อัตโนมัติ เช่น สถานีล้นตลิ่ง, แนวโน้มระดับน้ำ 24 ชม., น้ำในเขื่อนเปลี่ยนไปเท่าไรใน 7 วัน, ฝนหนัก, ฝนคาดการณ์ 3 วัน รวมถึงตารางจังหวัดที่ควรจับตา
- **แม่น้ำ** — ค้นหาและเรียงตามระดับน้ำหรือความเร็วที่น้ำขึ้น แตะดูกราฟย้อนหลังได้ และกด "พยากรณ์ ณ จุดนี้" ได้
- **เขื่อน** — % ความจุ น้ำใช้การได้ น้ำไหลเข้า/ระบาย และคาดการณ์ว่าจะเต็มในกี่วันถ้าน้ำไหลเข้าคงที่
- **ฝน** — ฝน 24 ชม. รายสถานี กราฟฝนรายวันย้อนหลัง และอันดับจังหวัด
- **อากาศ** — เลือกอำเภอ/เขต (928 แห่ง) หรือใช้ตำแหน่งปัจจุบัน · บอกช่วงเวลาที่คาดว่าฝนตกใน 3 วัน พร้อมความแรง (เล็กน้อย/ปานกลาง/หนัก/หนักมาก) ชั่วโมงที่หนักสุด และความมั่นใจจากจำนวนโมเดลที่เห็นตรงกัน · ตารางฝนรายชั่วโมง (แตะดูทีละชั่วโมงได้) · ตารางเทียบฝน 24 ชม. ทุกอำเภอในจังหวัด · ภาพรวม 10 วันเทียบ 3 โมเดล · อุณหภูมิ/ลม · แนวโน้มน้ำท่าจาก GloFAS
- **รายงาน** (ปุ่มมุมขวาบน) — สร้างรายงานสรุปทั้งประเทศหรือรายจังหวัด ตั้งชื่อรายงาน ใส่ชื่อผู้จัดทำ เลือกหัวข้อที่ต้องการ เขียนหมายเหตุเอง และกำหนดจำนวนแถวในตารางได้ แล้วบันทึกเป็น **รูปภาพ PNG** (เหมาะส่ง LINE) **PDF ขนาด A4** (แบ่งหน้าให้อัตโนมัติ) หรือ **พิมพ์** · บนมือถือจะเปิดเมนูแชร์ให้บันทึกลงเครื่องหรือส่งต่อได้ทันที

## ติดตั้ง (ครั้งเดียว ประมาณ 10 นาที)

> ขั้นตอนนี้ทำบนคอมพิวเตอร์สะดวกที่สุด ทำเสร็จแล้วใช้งานจากมือถืออย่างเดียวได้เลย

1. **สมัคร GitHub** ที่ https://github.com (ฟรี)
2. **สร้าง repository ใหม่** กด `+` → *New repository* ตั้งชื่อ เช่น `thai-water-monitor` เลือก **Public** (ต้องเป็น Public ถึงจะใช้ Actions และ Pages ได้ฟรีไม่จำกัด)
3. **อัปโหลดไฟล์** แตกไฟล์ zip ก่อน แล้วเลือกวิธีใดวิธีหนึ่ง
   - **ผ่านเว็บ:** ในหน้า repo กด *uploading an existing file* แล้วลากไฟล์และโฟลเดอร์ทั้งหมดใส่ ต้องมีโฟลเดอร์ `.github` ไปด้วย (บน Mac กด `Cmd+Shift+.` เพื่อแสดงโฟลเดอร์ที่ซ่อนอยู่)
   - **ผ่าน git:**
     ```bash
     cd thai-water-monitor
     git init && git add . && git commit -m "เริ่มโปรเจกต์"
     git branch -M main
     git remote add origin https://github.com/<ชื่อผู้ใช้>/thai-water-monitor.git
     git push -u origin main
     ```
4. **อนุญาตให้ Actions เขียนข้อมูลได้** ไปที่ *Settings → Actions → General → Workflow permissions* เลือก **Read and write permissions** แล้วกด Save
5. **รันรอบแรก** ไปที่แท็บ *Actions* → เลือก **อัปเดตข้อมูลน้ำ** → กด *Run workflow* แล้วรอ 1–2 นาทีจนขึ้นเครื่องหมายถูกสีเขียว
6. **เปิด GitHub Pages** ไปที่ *Settings → Pages* ตรง Source เลือก **Deploy from a branch** → Branch: **gh-pages** / **(root)** → Save
7. รอประมาณ 1 นาที แล้วเปิด `https://<ชื่อผู้ใช้>.github.io/thai-water-monitor/`

**เพิ่มเป็นแอปบนมือถือ**
- iPhone: เปิดใน Safari → ปุ่มแชร์ → *เพิ่มไปยังหน้าจอโฮม*
- Android: เปิดใน Chrome → เมนู ⋮ → *ติดตั้งแอป* หรือ *เพิ่มลงในหน้าจอหลัก*

## ให้อัปเดตตรงเวลา (แนะนำ)

ตัวตั้งเวลาในตัวของ GitHub เป็นแบบ "พยายามให้" ไม่รับประกันเวลา ในช่วงที่มีคนใช้เยอะ มักดีเลย์ 30 นาทีถึงหลายชั่วโมง หรือข้ามรอบไปเลย วิธีแก้คือให้บริการตั้งเวลาฟรีภายนอก (cron-job.org) สั่งให้ GitHub รันทุก 10–15 นาทีแทน ซึ่งตรงเวลาแทบทุกครั้ง

**ก. สร้างกุญแจ (token) ให้สั่งรันได้เฉพาะ repo นี้**
1. GitHub → รูปโปรไฟล์มุมขวาบน → **Settings** → เลื่อนลงล่างสุด **Developer settings**
2. **Personal access tokens → Fine-grained tokens → Generate new token**
3. ตั้งชื่อ เช่น `cron-water` และ Expiration เลือกได้นานสุด 1 ปี (ครบกำหนดต้องมาสร้างใหม่)
4. **Repository access:** เลือก *Only select repositories* → เลือก `thai-water-monitor`
5. **Permissions → Repository permissions → Actions:** เลือก **Read and write** (ไม่ต้องให้สิทธิ์อื่น)
6. กด **Generate token** แล้วคัดลอกเก็บไว้ทันที (ขึ้นต้นด้วย `github_pat_…` และจะแสดงแค่ครั้งเดียว)

**ข. ตั้งเวลาที่ cron-job.org**
1. สมัครฟรีที่ https://cron-job.org → **Create cronjob**
2. **URL:** `https://api.github.com/repos/<ชื่อผู้ใช้>/thai-water-monitor/actions/workflows/update.yml/dispatches`
3. **Execution schedule:** Every 15 minutes (หรือ 10 นาที)
4. แท็บ **Advanced**
   - Request method: **POST**
   - Headers เพิ่ม 3 บรรทัด:
     - `Authorization` = `Bearer github_pat_…` (token จากข้อ ก.)
     - `Accept` = `application/vnd.github+json`
     - `User-Agent` = `cron-job-water`
   - Request body: `{"ref":"main"}`
5. กด **Create** แล้วกด **Test run** ถ้าสำเร็จจะได้ผลเป็น **204** และในแท็บ Actions ของ repo จะมีรอบใหม่ขึ้นมาทันที

> ไม่ควรตั้งถี่กว่า 10 นาที เพราะต้นทางเองอัปเดตระดับน้ำราวทุก 10–60 นาที ฝนรายชั่วโมง และเขื่อนวันละครั้ง ดึงถี่กว่านั้นก็ได้ข้อมูลเดิม

## ลองในเครื่องก่อน (ไม่บังคับ)

ต้องมี Node.js 20 ขึ้นไป

```bash
npm run mock    # สร้างข้อมูลจำลองไว้ในโฟลเดอร์ out/
npm run serve   # เปิด http://localhost:8080
npm run fetch   # ดึงข้อมูลจริง (ต้องต่อเน็ต)
npm test        # ทดสอบตัวแปลงข้อมูล
```

## ข้อควรรู้

- **ความถี่:** workflow ตั้งไว้ทุก 15 นาที แต่ตัวตั้งเวลาของ GitHub อาจดีเลย์เป็นชั่วโมง ถ้าต้องการให้ตรงเวลา ให้ทำหัวข้อ "ให้อัปเดตตรงเวลา" ข้างบน ข้อมูลเขื่อนของกรมชลประทานอัปเดตวันละครั้งอยู่แล้ว
- **ประวัติจะเริ่มสะสมตั้งแต่วันที่ติดตั้ง** กราฟย้อนหลังจะค่อยๆ ยาวขึ้นเอง (แนวโน้ม 24 ชม. ต้องรอให้ครบ 1 วันก่อน)
- **ถ้าต้นทางล่ม** ระบบจะใช้ข้อมูลรอบก่อนแทน และหัวหน้าเว็บจะขึ้นจุดสีส้ม แตะที่ข้อความ "อัปเดต…" เพื่อโหลดใหม่ได้
- **GitHub จะหยุด workflow ตั้งเวลาอัตโนมัติ** ถ้า repo ไม่มีความเคลื่อนไหว 60 วัน ใน workflow มีขั้นตอนสั่งเปิดใช้งานซ้ำทุกเดือนไว้แล้ว แต่ถ้าหยุดจริง ให้เข้าแท็บ *Actions* แล้วกด *Enable workflow*
- **เขื่อน:** ข้อมูลครอบคลุมเฉพาะเขื่อนขนาดใหญ่ 35 แห่งของกรมชลประทาน จังหวัดที่ไม่มีเขื่อนใหญ่จะไม่มีข้อมูลในแท็บนี้
- **การใช้ข้อมูล:** API สาธารณะของ ThaiWater ไม่ได้ประกาศเงื่อนไขการใช้งานไว้ชัดเจน โปรเจกต์นี้จึงดึงข้อมูลจากฝั่งเซิร์ฟเวอร์วันละ 48 ครั้ง แล้วเก็บไว้ให้หน้าเว็บอ่านแทน เพื่อไม่ให้เป็นภาระกับต้นทาง และแสดงเครดิตแหล่งข้อมูลทุกหน้า เหมาะสำหรับใช้ส่วนตัว
- **บทวิเคราะห์เป็นการประเมินเบื้องต้นจากตัวเลข** ไม่ใช่ประกาศทางการ ในสถานการณ์น้ำท่วมควรติดตามกรมอุตุนิยมวิทยา กรมชลประทาน และ ปภ. ประกอบด้วย

## โครงสร้างไฟล์

```
.github/workflows/update.yml   ตั้งเวลาดึงข้อมูล + เผยแพร่ขึ้น GitHub Pages
scripts/fetch.mjs              ดึงข้อมูลจากต้นทาง รวมกับประวัติเดิม แล้วเขียนไฟล์ JSON
scripts/lib.mjs                ฟังก์ชันแปลงข้อมูลและสะสมประวัติ (มีชุดทดสอบ)
scripts/mock.mjs               สร้างข้อมูลจำลองไว้ลองในเครื่อง
site/                          หน้าเว็บ (HTML/CSS/JS ล้วน ไม่ต้อง build)
test/                          ชุดทดสอบ
```

## ปรับแต่ง

- **ความถี่ในการดึง:** แก้ `cron` ใน `.github/workflows/update.yml` (ขั้นต่ำที่ GitHub รองรับคือทุก 5 นาที)
- **ระยะเวลาเก็บประวัติ:** แก้ `keepDays` ในฟังก์ชัน `merge…History` ใน `scripts/lib.mjs`
- **เกณฑ์สี:** แก้ `RIVER_BANDS` และ `DAM_BANDS` ใน `site/app.js`
